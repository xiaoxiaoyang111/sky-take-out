# 简历描述与项目答辩

## 可以使用的项目描述

**龙院摄影器材租赁系统｜Java后端项目**

技术栈：Spring Boot、MyBatis、MySQL、Redis、JWT、Vue3、DeepSeek API。

- 围绕器材型号与独立实物建模，实现按租期报价、预约、确认、领取、归还与评价流程；通过事务、统一行锁顺序和占用区间校验，防止同一实物在重叠租期重复分配。
- 使用用户级requestId实现预约重试幂等，并校验同一请求编号的业务参数一致性；结合角色鉴权和订单归属校验隔离客户与员工操作。
- 使用Redis缓存公开目录，以提交后版本切换与Lua条件写入避免旧查询回填当前缓存；库存分配、实时费用和订单以MySQL为准。
- 接入DeepSeek租赁咨询，结合公开器材资料生成回答，由后端再次核验器材名称与上架状态生成站内跳转；Redis保存限长会话，模型不执行业务写操作。
- 为预约并发、事务回滚、权限、头像持久化等补充自动化验证，并提供真实HTTP验收、有限规模性能验证与生产部署配置。

这些是代码与验证的事实，不应机械照抄。投递前只保留你能解释的条目；若不能完整说明某项，先学习再写入。可以如实说明项目基于学习项目进行业务改造与AI辅助开发，不写成独立完成生产商业系统。

## 3分钟介绍框架

先用30秒说明场景：单门店按日期租赁，一台实物在不同日期可被不同客户预约，到店交接，不处理线上资金。接着介绍客户和员工的操作闭环。重点讲防超订与幂等两个设计，再讲缓存与小影。最后主动说明规模与边界：个人学习/演示项目，有自动化及本机HTTP验证，尚无生产运营数据。

## 必须能解释的8个问题

1. **为什么要分型号和实物？** 型号决定展示与定价，实物承载编号、维护状态与时间段占用；一单分配一个实物。
2. **库存查询还有1件，为什么提交时仍可能失败？** 报价不锁定库存，另一个事务可能先提交；创建事务锁型号后做当前读并分配，最后一件只能给一单。
3. **为什么锁顺序重要？** 预约、型号/实物变更和订单流转先锁equipment，再按流程锁订单/实物；避免不同流程反向持锁导致循环等待。死锁仍需数据库层面监控，不能宣称完全消除。
4. **幂等与限流有什么区别？** 相同用户+requestId重试同参数得到同一订单；它防重复业务，不是禁止用户频繁请求。参数不同复用同键应拒绝。
5. **事务回滚如何证明？** 在订单写入后让事件写入失败，检查订单不存在、实物仍可租；不能用进入Controller之前的校验失败来证明回滚。
6. **缓存为什么提交后再失效？** 提交前失效可能被并发查询用未提交旧数据重新填充；版本切换隔离旧条目，Lua只允许当前版本写入。失效失败仍有60秒TTL兜底。
7. **JWT有了为什么还校验订单归属？** 令牌只证明身份与角色；知道订单ID不代表拥有该订单。管理员操作还检查员工是否启用。
8. **小影如何避免推荐不存在的器材？** 提供公开目录、要求完整名称，并在回答后再次查当前公开状态；链接由服务端生成。这样只能降低推荐错误，不能保证模型所有文字事实正确。

## 两次实际练习

**练习一：独立修改需求。** 在隔离数据中把某个日期规则或字段约束改成新要求，补测试并解释受影响的Controller、Service、Mapper、前端与表。不要只跟着复制答案。

**练习二：独立排障。** 在本机临时停止Redis或把模型端点设置为不可达地址，区分缓存降级、助手错误和租赁核心流程；恢复配置后再验证。不得在正式环境随意停服务。
