# 龙院摄影器材演示路线

目标：用5～8分钟展示租赁闭环与两个后端设计点。演示前确认本机 MySQL、Redis、后端与8082网页可用；使用自建测试账号，不展示密码、令牌、真实客户信息或IDEA环境变量。

## 演示顺序

1. 打开首页：搜索器材，选择领取/归还日期，进入详情查看即时可租数量、日租金和押金。说明“归还日不计费，报价不锁库存”。
2. 登录客户账号：收藏器材；在个人中心点击头像进入独立资料页，修改昵称、上传PNG/JPG，返回确认头像显示。
3. 提交预约：进入“全部订单”查看待确认状态与订单事件。说明客户端生成requestId，重试相同参数返回同一订单。
4. 使用另一浏览器会话登录员工：查看订单，确认后领取，再填写验收说明登记归还。演示当天领取需选择今天开始的租期。
5. 返回客户：查看已归还、填写评价，展示历史评价。
6. 打开小影：先看到问候，再询问“我是摄影新手，想拍人像，请推荐本店器材”。点击回答中经过验证的器材名跳转详情。不要声称模型知道即时库存或能代客下单。
7. 展示测试证据：`VALIDATION.md`、HTTP报告和预约事务代码，解释20个竞争预约为什么只会成功1单。

## 自动验收替代入口

`node scripts/Verify-Rental.mjs --model` 会通过真实HTTP完成相应后端流程，创建独立临时账号、员工、器材与订单，验证后清理。JSON报告不包含账号密码或令牌。没有模型密钥时不加`--model`。

DOM交互回归运行 `npm run test:ui`，覆盖实际Vue组件事件及路由守卫，网络使用替身；不能把该结果说成浏览器真实点击录像。

## 演示前检查

- 模型余额和服务端网络可用，代理不应指向错误机器；超时不自动重复付费请求。
- 避免同时从多个窗口操作同一订单，准备一个未占用的测试实物。
- 若模型暂不可用，正常说明外部服务失败，转而展示规则查询和租赁主流程，不展示假回答。
- 本仓库暂无本轮完整浏览器录像；要录制时按上述路线实操，录完确认无凭据与真实客户数据。
